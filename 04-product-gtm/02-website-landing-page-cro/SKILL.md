# Website & Landing Page Conversion Research Skill

## Purpose
Audit Reznt web pages for audience clarity, evidence, friction, and conversion opportunities.

## When to invoke
Invoke this skill when a Reznt team member needs the task described above completed independently.

## Required inputs
- URL(s) to inspect.
- Target audience and desired conversion.
- Analytics/heatmap/session data if authorized and available.

If a critical input is missing, state the assumption or ask one concise clarification. Do not block useful work when reasonable assumptions can be clearly labeled.

## Operating procedure
1. Review the page as a specific buyer: identify audience, problem, promise, product explanation, proof, objections, and CTA.
2. Check message match between traffic source, ad/query/social post, and landing page.
3. Review hierarchy, readability, navigation, mobile usability, page speed/accessibility only where tools permit.
4. Identify proof gaps: customer evidence, demo, workflow examples, security/privacy explanation, pricing clarity, and integration details.
5. Use analytics to locate drop-offs if provided; otherwise label friction observations as heuristic, not measured behavior.
6. Prioritize hypotheses by impact, confidence, and effort.
7. Create an experiment brief with baseline, variant, primary metric, guardrails, and decision rule.

## Required output
- Page audit with evidence/screenshots or specific page references when available.
- Friction list ranked by priority.
- Copy/layout hypotheses and test plan.
- Required tracking events and research-log records.

## Quality and safety checks
Do not claim an observed user behavior without analytics evidence. Avoid dark patterns and misleading urgency.
