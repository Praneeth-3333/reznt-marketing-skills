# Vertical Landing Page Brief Skill

## Purpose
Create an evidence-backed brief for a Reznt landing page tailored to one industry or use case.

## When to invoke
Invoke this skill when a Reznt team member needs the task described above completed independently.

## Required inputs
- Vertical and buyer role.
- Geography/language.
- Target conversion and available proof.

If a critical input is missing, state the assumption or ask one concise clarification. Do not block useful work when reasonable assumptions can be clearly labeled.

## Operating procedure
1. Use ICP, vertical, VoC, SEO, and competitor evidence to define the page audience.
2. Identify the primary workflow problem and one clear value proposition.
3. Map the page: headline, problem, workflow, capabilities, proof, governance/trust, objections, CTA, FAQs.
4. Match each capability claim to verified product evidence.
5. Identify keywords and search intent if SEO is a goal.
6. List proof assets needed: demo, screenshots, approved quotes, measured results, or integrations.
7. Specify analytics events and a test plan.

## Required output
- Page strategy and outline.
- Draft headline/subhead and section briefs.
- Claims/proof matrix.
- SEO intent and CTA recommendation.
- Measurement and research-log records.

## Quality and safety checks
Do not publish industry-specific claims without validating the workflow and product fit. Never fabricate vertical customer logos or case studies.

## Reznt context
Use `00-foundation/REZNT_BRAND_BRIEF.md` and `00-foundation/RESEARCH_STANDARDS.md`. Keep Reznt's positioning as an AI Revenue Operator for conversation-led businesses in view. Do not reduce the value proposition to “automated replies” unless the task specifically concerns that feature.

## Related skills
Use related skills when the task requires deeper evidence or execution.

## Research logging
For material findings, produce a completed record using `00-foundation/RESEARCH_LOG_TEMPLATE.md`. Include source URLs and evidence labels. Never claim that you saved data to a system unless the platform actually provides and confirms that capability.
